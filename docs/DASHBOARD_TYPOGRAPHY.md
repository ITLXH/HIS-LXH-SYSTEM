# Dashboard Typography

Two rendering modes share the same DOM (`#dashboardPrintArea` under `public/partials/views/dashboard.html`) but resolve different font sizes via mutually-exclusive selector chains in `src/style.css`.

| Mode | Selector chain | Purpose |
|------|----------------|---------|
| **On-screen** | `#dashboardPrintArea.dashboard-a4-sheet:not(.dashboard-export-mode) …` | Interactive view inside the app shell |
| **PDF export** | `#dashboardPrintArea.dashboard-export-mode …` and `.dashboard-export-sheet …` | Two-page A4 landscape report generated by `exportDashboardPDF()` |

The PDF path adds the `dashboard-export-mode` class before html2canvas snapshots the DOM and removes it after, so the on-screen rules are inert during the snapshot.

## 2026-07-06 — Bump on-screen fonts

User feedback: "ຊ່ວຍປັບ font ໃຫ້ໃຫຍ່ຂື້ນຕື່ມ". The A4-optimized sizes leaked to the on-screen mode and felt cramped. Only the on-screen chain and the Chart.js canvas fonts were touched; PDF export sizes are unchanged.

| Element | Before | After | Location |
|--------|--------|-------|----------|
| Panel head `h6` | 12px | 15px | `src/style.css` `.dashboard-report-panel-head h6` (non-export chain) |
| Panel head `p` / split-title | 10px | 12.5px | same file |
| KPI title | 13px | 15px | `.dashboard-kpi-title` (non-export chain) |
| KPI value | 3.1rem | 3.4rem | `.dashboard-kpi-value` (non-export chain) |
| KPI note | 12.5px | 14px | `.dashboard-kpi-note` (non-export chain) |
| Toolbar subtitle | 11.5px | 13px | `public/partials/views/dashboard.html:6` inline style |
| Empty-state overlay msg (canvas) | 13px | 15px | `src/main.js` `dashboardNoDataOverlay` plugin |
| Empty-state overlay sub (canvas) | 11px | 13px | same |
| Compact chart legend | 8px | 11px | `createChart()` compact-dashboard branch |
| Compact chart X-tick | 8px | 11px | same |
| Compact chart Y-tick | 9px | 12px | same |
| Compact chart datalabel | 8px | 11px | same |

The compact-dashboard set covers `chartTopServices, chartRevenue, chartSpecialist, chartGender, chartDept, chartSite, chartTime, chartAge, chartMarketing, chartInsurance, chartOrganization, chartOccupation, chartProvinceBreakdown, chartDistrictBreakdown` — every chart inside the summary + detail spread. Non-compact defaults (used elsewhere in the app) were also lifted from 10→12 and 11→13 so any dashboard chart that ever falls off the compact list still reads larger than before.

Verification note: dashboard is behind Supabase login and the preview server is not directly reachable from this session's browser tab. Vite reported no build/parse errors after the edits.

## 2026-07-06 — Bar-chart datalabels for 7+ items

Follow-up feedback: "ກາບນີ້ບໍ່ມີໂຕເລກສະແດງ" — Occupation chart (7 bars visible) rendered without value labels. Every compact chart uses `createChart()` in [src/main.js](../src/main.js), and its datalabels `display` callback previously suppressed labels above `safeData.length > 6` for horizontal and `> 5` for vertical compact charts, to avoid crowding. Occupation, Insurance, Organization, Top 5 Doctors, Province and District are all horizontal Top-8/Top-10 panels, so any run with 7+ non-zero rows dropped all numeric labels.

Raised the display ceiling in `createChart()` to `isHorizontal ? 12 : 8`. Rationale for keeping a ceiling (rather than always-on):
- The dashboard spread has narrow tiles; 12+ horizontal bars still risk overlap and the automatic drop-out remains a useful guard.
- Vertical bars stack labels above the bar (`align: 'top'`) — 9+ labels on a compact tile begin to collide with the panel title, so 8 is a safer cap.
